# 枚举与缩小候选

[返回总目录](../../README.md)

## 通用思路

先算枚举量：候选数量乘单次验证代价。如果总量已经足够小，就直接写正确的枚举。重点是候选完整、不重复、验证与题意严格一致，而不是先找更高级算法。

常见的缩小方式有：倒序找到第一个有效覆盖；从一次操作后的结果反推有限原状态；固定一侧后增量维护另一侧。若枚举一个对象很难，试着枚举决定该对象的少量参数。

## 如何写稳定的检查器

把 `check(candidate)` 独立出来，先写“什么时候不合法”，任一条件不满足就返回 false。数字锁要保留前导零，几何覆盖要区分闭边界与开边界，方案去重要按对象本身而不是生成路径。

暴力程序也有用途：以后推贪心或计数公式时，用它在小规模枚举所有情况，对照新算法。先有可运行的题意模型，往往比直接猜结论更稳。

## 常见错误

- 只看循环层数，不代入实际范围估计总次数。
- 枚举到了候选，却漏验证某条规则。
- 去重过度，合并了题目认为不同的方案；或同一个候选由多个操作生成后重复计数。
- 把“第一处命中”用于没有顺序单调性的题目。

## 练习顺序

铺地毯 → 无线网络发射器选址 → 密码锁。密码锁先枚举全部五位数，再用 81 个反向候选替换，比较两种实现的稳定性。
