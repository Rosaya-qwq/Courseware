# 国王游戏

2012 NOIP 提高组 · Day 1 · T2 · 提高 · 建议独立尝试 60 分钟

[返回总目录](../../README.md) · [分类总结](../../categories/greedy/README.md)

## 题意

国王固定在最前，第 $i$ 个大臣所得为前面所有人左手数的乘积除以自己的右手数并向下取整。调整大臣顺序，使最大所得最小。

## 关键部分分

- 极小 $n$：枚举所有排列，逐个计算最大所得，$O(n!n)$；只能用于很小的 $n$ 和对拍，不能据此声称覆盖 $n\le10$ 的整档。
- 仍在 64 位范围内的数据：先实现按 $a_ib_i$ 排序的贪心，用 64 位维护乘积。原题有答案不超过 $10^9$ 的数据，但**这不保证中间乘积不溢出**，不能以答案小作为不用高精度的理由。
- 稳妥保底可用同一排序算法配高精度乘小整数、除小整数，实际上已经接近正解；不建议另写没有正确性保证的排序规则。

## 做法

大臣按 $a_ib_i$ 从小到大排列。考虑相邻两人 $i,j$，设此前乘积为 $P$；忽略向下取整时，两种顺序的局部最大值分别为

$$P\max(1/b_i,a_i/b_j),\qquad P\max(1/b_j,a_j/b_i).$$

若 $a_ib_i\le a_jb_j$，则前者不超过后者：$1/b_i\le a_j/b_i$，且 $a_i/b_j\le a_j/b_i$。后续前缀乘积相同；向下取整保持这个不等式，因此交换逆序对不劣。

初始化大整数乘积为国王的 $a_0$。依次先计算 `product / b[i]` 更新最大值，再乘上 `a[i]`。

## 实现与复杂度

十进制或大进制数组实现乘小整数和除小整数。若最大位数为 $D$，时间 $O(n\log n+nD)$，空间 $O(D+n)$。原题 $n\le1000$；排序乘积比较用 64 位。不能把国王参与排序，不能先乘当前大臣再计算其奖赏。
